# Dataset decision: escalate ambiguous organization records

**Recommendation for review, November 4, 2026:** choose Crossref funder-name matching. Use the separately released **human-labeled deposited names**, not pairs manufactured solely from canonical registry aliases. Match two funding-organization name records to each other, based on whether they identify the same organization. This retains the escalation question while changing the business domain from product reconciliation to funding-data reconciliation. The decision concerns source selection only.

| Source | Identity evidence and practical difficulty | Rights, access and estimated effort |
|---|---|---|
| **Crossref Open Funder Registry (OFR)** | Preferred names, aliases, country, funder DOI and hierarchy. An alias and its preferred name share a curated ID, but easy aliases inflate accuracy; short names can refer to different funders. The NSF record includes both “US NSF” and “NSF” plus organizational relationships. A division is not automatically a safe negative for its parent. | Crossref explicitly licenses the RDF registry CC0. Registry metadata is suitable for external processing; no paper text is needed. Low engineering effort, moderate review. Crossref now targets **ROR** for new funder matching: do not equate an OFR DOI with a ROR ID. [Registry license and fields](https://www.crossref.org/documentation/funder-registry/accessing-the-funder-registry/) · [NSF record](https://api.crossref.org/funders/100000001) · [Crossref transition](https://www.crossref.org/blog/improving-how-funding-connects-to-research-outputs/) |
| **Crossref deposited funder names → ROR (preferred)** | Real spelling, language and organizational variation. A human evaluator assigned zero, one or multiple ROR IDs; alternate labels identify known ambiguities. Same single ID yields a positive; distinct single IDs yield only *candidate* negatives pending relationship and ambiguity checks. Better evidence of actual input difficulty than registry aliases, without using a model's predictions as truth. | The **label file itself** is CC0; no reliance on the registry license extending to another file. A 495,351-byte release suffices. Use only organization-name metadata in any approved request, no people, papers or acknowledgments. Estimate 0.5–1 engineer day plus 2–4 reviewer hours for a bounded 24-pair audit and freeze, not the held-out study. [Release, files, license and labeling method](https://zenodo.org/records/19699937) · [Crossref sampling rationale](https://www.crossref.org/blog/matching-funders-in-scholarly-metadata-linking-names-to-ror-ids/) |
| **OpenAlex institutions** | OpenAlex IDs, ROR links, aliases, acronyms and lineage support registry-derived pairs. Inspected Michigan record I27837315: UMich and the French name are attested variants; “UM” alone is ambiguous. Real affiliation strings are harder, but many institution assignments are produced by a matcher, so using them as truth risks evaluating agreement with that matcher. Distinct OpenAlex IDs across roles are not proof of different organizations. | OpenAlex metadata is CC0. Use institution metadata only; linked papers/content are outside this rationale. A single unauthenticated metadata lookup worked; scaled pagination has separate API-key/usage rules. ~0.5–1 day for registry aliases; ~1–2 days plus independent adjudication for noisy affiliations. [License](https://help.openalex.org/access/pricing/) · [Institution fields and limitations](https://help.openalex.org/data/institutions/) · [Access rules](https://help.openalex.org/api/authentication/) |
| **WDC Products (paused)** | Direct binary product pairs, hard negatives and real merchant variation, with known cluster-label errors. Useful baseline; different domain. | Public research availability and the code license do not establish redistribution or external API transmission rights for merchant text. No substantiating permission found. No further investment or transmission proposed. [Benchmark](https://webdatacommons.org/largescaleproductcorpus/wdc-products/) · [Software license](https://github.com/wbsg-uni-mannheim/wdcproducts/blob/main/LICENSE) |

**Measured feasibility.** Inspected Crossref v1 (2026-04-22), JSONL SHA-256 **7c5c4bae3b71d029082a1337299f5a4c21014ddd2012064be38893fda4b5c0c8**, matching the publisher's MD5. Of 3,505 names, 1,692 have exactly one primary ID and no alternates. The other 1,813 fail this first screen; an empty list is not evidence that two unmatched names differ. To reproduce the counts: exclude preview range seq_no 0–19, take one output and no alternates, NFKC/casefold each name, join contiguous alphanumeric words with spaces and deduplicate normalized names inside each ROR group. Of 1,100 remaining IDs, **220** have at least two distinct normalized names (356 possible disjoint within-ID pairs by summing floor(group size/2)). These are upper bounds before semantic review, not a prepared dataset. Only aggregate counts were retained; no pair file, importer or model inputs were built. The manual annotations are Crossref's; no independent human adjudication by this project occurred.

**Next decision.** Approve at most a 24-pair *offline feasibility audit*: target 12 same-ID variants and 12 lexically similar different-ID pairs. Require one unambiguous referent per visible name, active IDs in a pinned ROR version, no alternate, related, predecessor, successor or parent/child interpretations; exclude globally conflicting identical names and names requiring unprovided context. Sample deterministically within preset similarity bands, independently of model outputs. Have two reviewers resolve identity from evidence, record disagreements, and reject unresolved cases. Keep IDs, labels, weights and reviewer notes out of prompts. Partition by organization and shared name family before choosing cases; freeze development threshold, one organization-specific prompt and a separate untouched split before held-out evaluation.

A balanced audit measures neither production prevalence nor end-to-end entity retrieval. Frequency-weighted sampling, public benchmark memorization and non-independent name variants limit generalization. If the audit passes, the existing acquisition/replay path can compare 0/25/50/100% uncertainty-ranked escalation on identical pairs. Record paired changes, F1, false positives/negatives, failures, latency and marginal F1 per estimated API dollar. A new prompt, case manifest, settings, privacy screen, budget and explicit execution approval would be required. No live run or held-out evaluation is authorized.
